## 0. 执行摘要

### 0.1 一句话结论

**面向海外用户与客户，不为五类用户做五个产品，而是做「一个行情与过程内核 + 五套角色视图 + 三种交付形态 + 一条用户授权实盘通道」**：小白与交易员共用同一套 C 端代码、只切换信息密度与引导强度；量化团队、基金公司、投顾共用一套「工作区 / 权限 / 审计 / API」底座；**实盘通过用户本人向券商 OAuth 授权接入，平台不托管资金、不代客操作，并把真实成交回灌到分析与复盘闭环**。

**海外定位决定了三件事**（详见 §13）：① 不与券商自建 MCP/AI 正面竞争「读自己账户」，差异化在**跨券商聚合 + 跨资产/跨实体分析 + 可审计的合规证据**；② 交易接入走券商 OAuth/开放平台合同，**不依赖任何强制开放 API 法规**；③ 数据架构默认「全球控制平面 + 区域数据平面」，满足 GDPR / DORA / SEC Reg S-P / HKIDR 的存储、留存与同意要求。

### 0.2 五类用户的核心矛盾与产品应答

| 用户 | 真正要解决的问题 | 产品应答（一句话） | 本季度优先级 |
|---|---|---|---|
| 小白用户 | 看不懂、怕亏、不知道下一步做什么 | **引导式视图**：少指标、白话解释、分级风险提示、三步走完首次路径；授权账户仅做**历史交易学习回顾**，不开放实盘下单 | **P0** |
| 专业交易员 | 看盘慢、动作碎、信息散在多处 | **高密度工作台 + 授权实盘**：一屏决策、键盘主路径、多图同屏、真实持仓/成交同步 | **P0**（实盘 P3） |
| 量化团队/公司 | 数据不可信、实验不可复现、结果交付不了 | **轻量策略工作台 + 数据/API + 受控执行**：可复现 run、小范围参数实验、策略信号人工确认后落到券商 | **P1**（API 最小集 P0，实盘 P3/P4） |
| 基金公司 | 组合风险看不见、研究流程无留痕、权限混在一起 | **组合与风险视图 + 研究流程 + 审计报表**，并同步**真实账户成交**做归因（不接柜台、不做执行） | **P2**（需付费试点） |
| 投顾 | 客户组合跟不过来、报告靠手工、适当性说不清 | **客户组合跟踪 + 报告沟通 + 适当性辅助**；客户**自行授权**后只读查看其交易数据，**投顾绝不代客下单** | **P1/P2**（合规评审先行） |

### 0.3 排序结论（砍需求时的默认答案）

1. **先锁定目标辖区与聚合商**：首版只选 1–2 个辖区（建议美国 + 新加坡/中国香港海外华人），并在写日期前拿到 SnapTrade/Plaid 的生产报价；没有报价不承诺上线时间。
2. **先做 C 端两种视图**：角色切换 + 小白引导 + 交易员工作台密度。这两类用户已经存在，投入产出最短。
3. **再做共享底座**：工作区 / RBAC / 审计 / API Key / 数据字典。这是后三类用户的共同前置。
4. **实盘单独分期、单独评审**：P3 先做「用户授权 + 人工确认下单 + 成交同步」，P4 再评估「受控自动执行」。**任何阶段都不默认开启实盘、不自动提交 AI/策略订单**。
5. **B 端只做「看得见、说得清、管得住」**：组合风险视图、策略复现、客户报告、适当性留痕。执行能力只到「用户自己的券商账户」为止，不接机构柜台/OMS。
6. **任何 B 端功能上线前必须有付费试点或合同**。

### 0.4 必须现在就定的决策

| # | 决策点 | 建议 | 影响 |
|---|---|---|---|
| D1 | 角色视图是「换路由」还是「换皮」 | **换配置不换路由**：同一 `/markets`、`/symbol/...`，由 `viewMode = guide \| pro` 控制密度；B 端另起 `/workspace/[id]` | 守住一套代码库 |
| D2 | 量化做到什么深度 | **轻量策略工作台**，非 Quant IDE；上限：单标的/小篮、日 K、参数 3–5 档、Worker 异步 | 工程量与叙事边界 |
| D3 | 投顾适当性做到什么深度 | **辅助层**：问卷 + 等级映射 + 匹配校验 + 二次确认留痕 + 外部附件；不自建双录 | 合规红线 |
| **D4** | **实盘首版是否允许自动执行** | **P3 仅人工确认**；P4 再评估「受控自动执行」（单标的、限笔数、限额度、可随时停），默认关闭 | 决定风控与合规评审范围 |
| **D5** | **小白视图是否开放实盘下单** | **不开放**；只展示已授权账户的历史交易回顾，想交易须切 pro 并再确认一次 | 保护新用户，避免误操作 |
| **D6** | **投顾能否看客户交易数据** | **仅客户本人授权后只读可见**，可撤销、全留痕；**绝不代客户下单、不采集客户凭证** | 合规红线 |
| **D7** | **券商条款若禁止第三方下单** | 降级为**仅分析模式**：用户导出/上传对账单 CSV，平台做交易数据分析，不做下单 | 保底交付路径 |
| **D8** | **首版目标辖区** | 建议 **美国 + 新加坡/中国香港海外华人** 二选一或并行；欧盟因 MiFID II 最佳执行与 DORA 成本高，放 P2 后 | 决定合规文案、留存期、同意链路与数据平面 |
| **D9** | **券商覆盖策略** | **直连 + 聚合层并行**：长桥/老虎直连做深度，SnapTrade/Plaid 做广度；不自己维护数百条券商连接 | 决定 connector 架构与月度成本 |

## 1. 背景、问题与机会

### 1.1 现状（以仓库实现为准）

- 已具备：多市场 L1 行情（美/港/A/加密，多源 failover + BYOK）、K 线与指标、AI 冷静层、模拟盘 + 风控 P0/P1、规则实验室（模板/回放/对比/参数小表/多标的篮）、Learn、Tools、复盘、提醒、Free/Pro 权益。A 股行情仅作参考数据，**不面向内地客户提供交易功能**（见 §3.5）。
- **海外券商与聚合层现状（选型输入）**：
  - 券商自建 MCP/AI 已成为「读自己账户」的默认竞品：IBKR、Robinhood、Webull、Longbridge、Tiger、富途/moomoo 均提供免费连接器或 AI 助手，且账户隔离更彻底。
  - 聚合层：SnapTrade（40+ 券商，约 16 家可下单；$100/月 + $1/用户/月日频或 $2 实时）、Plaid Investments（约 3,200 家机构，只读）、Yodlee（标识符最全）、Akoya（银行自有 API 网络）、Wealthica（加拿大补位）。
  - **IBKR TWS API 为「非商业许可」**，不得用于向第三方收费的软件；商业化须走机构授权谈判。Schwab Trader API 为标准 OAuth 2.0，但品种覆盖有限（期货/外汇/非美股票/债券不支持）。
  - 聚合商返回的投资账户价格是券商报送价、不是行情源；**估值须用自有行情按数量重算**。Plaid 等因标识符授权不足会置空 CUSIP/ISIN，主体匹配需自建映射或采购许可。
- **实盘相关已有基础**：
  - 长桥 / 富途 **OAuth 2.1 + PKCE** 授权链路已实现（`/api/oauth/{longbridge,futu}/start|callback`），state 校验、token 交换、加密落库（`UserMarketCredential`）已具备。
  - `src/lib/broker/index.ts` 已定义 `BrokerGateway` 接口（`placeOrder` / `cancelOrder`），但 `getBrokerGateway()` 恒返回 `null`，`ready` 恒为 `false`。
  - `UserServiceCredential` 提供通用加密凭证存储；`CREDENTIALS_ENCRYPTION_KEY` 已用于 AES-256-GCM。
  - 富途 `sim-trade` 云端模拟交易已有对接规划（[symbol-advanced-and-futu-paper](./symbol-advanced-and-futu-paper.md) §2）。
- 交付形态已有雏形：在线 Free/Pro、源码/私有部署分栏（`/pricing`）。
- 真实约束：Next.js 15 + Prisma/PostgreSQL + Worker；单文件 500 行上限；行情 WS 是主要流量开销。

### 1.2 问题

| 问题 | 表现 | 后果 |
|---|---|---|
| 一套界面服务所有人 | 小白看到一堆指标；交易员被引导卡片挡住主路径 | 两头不讨好 |
| 角色无法被识别 | 没有 role / workspace 概念，埋点分不出人群 | 无法按角色衡量与定价 |
| B 端需求被当成功能堆砌 | 机构边界文档说「不做」，销售侧又收到组合、权限、报表诉求 | 路线图失焦 |
| 数据与实验能力没有产品化 | 已有 K 线 API 与回放引擎，但没有 API Key、数据字典、可复现 run | 团队客户无法采购 |
| **模拟与真实割裂** | 用户在模拟盘练得很好，真实成交却散落在券商 App，无法回灌复盘 | **过程纪律闭环断在最后一公里** |
| **授权链路没有转化为交易能力** | OAuth 已用于行情 BYOK，但交易 scope、账户选择、下单确认、成交同步都还没有 | 已投入的授权基建价值只发挥了一半 |
| 流量与性能债 | WS 全量推送、报价状态不可见、弱网无降级 | B 端 SLA 无从谈起，C 端成本失控 |

### 1.3 机会

- **边际成本递减**：五类角色共用同一份行情、标的、AI、模拟、规则内核，差异集中在视图层与权限层。
- **差异化叙事清晰**：海外「读自己账户」已被券商自建 MCP/AI 占满；TAMP 被 Addepar / Orion / 老虎 TradingFront / 富途大象财富占据；机构 TCA 被 Bloomberg / TT 占据。**留给新进入者的空位是「跨券商聚合 + 跨资产/跨实体 + 可审计的过程与合规证据」**，即 **「过程纪律 × 用户授权实盘 × 跨券商 × 可审计」**，不是再造一个行情终端。
- **合规即卖点**：EU Delegated Regulation 2026/825 把最佳执行从公开披露改为常设内部举证（2028-02-12 适用）；SEC Reg S-P 修订要求服务商 72 小时通报、30 天通知客户；HKIDR 把明示同意做成可被检查的产品功能。**这些比「AI 洞察」更容易定价**（详见 §13.4）。
- **已有资产可直接复用**：OAuth/PKCE 与加密凭证已落地；规则实验室是量化策略工作台的 P0；模拟盘与复盘是交易数据分析的底稿。
- **BYOB（Bring Your Own Broker）降低合规与资金风险**：用户自己在券商完成 KYC 与适当性，平台只做工具与数据分析，不碰资金、不做代客。**接入权来自合同 + 用户同意，不是法定权利**（美国 CFPB 1033 规则目前未生效，且不覆盖投资账户）。

### 1.4 成功定义（3 个月可感知 + 实盘分期目标）

**C 端 / 团队（3 个月）**

1. 新用户首访 3 分钟内完成「看一张图 → 加自选 → 走一次引导分析」。
2. 交易员一屏内完成「看价 → 看图 → 设条件 → 生成草稿」，主路径 80% 可键盘完成。
3. 有一个可复现的策略 run：给定 run id 能还原数据快照、规则版本、参数与结果。
4. 有一个付费试点客户能在工作区看到组合风险视图并导出带审计痕迹的报表。
5. 有一份投顾报告样例：自动生成、带免责与数据来源、客户链接可过期、适当性不匹配有留痕。

**实盘（P3/P4 分期目标）**

6. 用户可在设置页完成券商 OAuth 授权，明确选择账户，看到 scope 与撤销入口。
7. 真实下单走双步确认，AI/策略草稿**从不自动提交**；每笔订单有幂等键与审计记录。
8. 券商成交/持仓能同步回平台，并在复盘页生成「真实交易行为分析」（胜率、盈亏比、持仓时长、纪律执行率、行为偏差）。
9. 一键断开授权后，所有实盘动作立即停止，历史分析数据仍可查看。

## 2. 用户与场景分析

### 2.1 角色画像

| 角色 | 典型画像 | 核心任务（JTBD） | 成功定义 | 付费意愿 | 硬约束 |
|---|---|---|---|---|---|
| 小白用户 | 入市 <1 年，术语陌生，怕被套 | 「看懂状态，我该先学什么」 | 不靠外部教程走完一次分析 | 低（Free 为主） | 不开放实盘下单；不得输出买卖建议 |
| 专业交易员 | 波段 1–10 日，盯 3–20 只标的 | 「最短时间判断结构、设条件、执行（含真实账户）」 | 一屏决策；模拟与真实都能复盘 | 中高（Pro + BYOK + 券商授权） | 实盘双步确认；不刷单；不做默认实盘 |
| 量化团队 | 研究员 2–20 人，有工程能力 | 「验证规则可复现，并让同事复现；信号能受控落到真实账户」 | run 可复现；真实成交可回灌分析 | 高（团队席位 + API 配额） | 非 IDE；非全市场扫描；P3 只人工确认 |
| 基金公司 | 基金经理/研究员/风控/合规/运营 | 「看清组合暴露与风险，研究流程留痕，真实成交可归因」 | 越权为 0；关键操作 100% 可追溯 | 高、周期长、要私有化 | 非 OMS/EMS；不接柜台；不做估值核算 |
| 投顾 | 持牌投顾，服务 20–300 位客户 | 「给客户讲清组合变化，报告自动出，适当性留痕」 | 报告 10 分钟生成；客户授权清晰可撤销 | 中高（顾问席位） | **绝不代客下单/持有客户凭证**；不自建双录 |

### 2.2 关键用户故事

**小白用户**

- US-B1：作为新股民，我想打开一只股票就看到「现在是什么状态、为什么」。
- US-B2：作为怕亏的用户，我想在波动异常时收到明确但不过度吓人的提示。
- US-B3：作为首次访问者，我想被带着完成「看盘 → 加自选 → 引导分析 → 模拟练习」。
- **US-B4**：作为已在券商交易过的新手，我想在授权后**看到自己过去几笔交易的白话复盘**，帮我理解哪里做错了——但我不希望在这里直接下单。

**专业交易员**

- US-T1：我想自选、主图、盘口、新闻和计划在一屏内。
- US-T2：我想用快捷键完成搜索、周期切换、设提醒、生成下单草稿。
- US-T3：我想 1/2/4 格同屏且十字光标同步，并保存布局。
- US-T4：我想知道当前报价来自哪个源、延迟多少、是否断线。
- **US-T5**：作为已授权券商的用户，我想在确认后直接下一笔真实限价单，并在成交后看到它与我的计划/规则标签的偏差。
- **US-T6**：我想看真实账户的持仓与今日成交，和模拟盘并列对照。

**量化团队**

- US-Q1：我想用结构化规则定义策略并跑历史回放，不用写代码。
- US-Q2：作为复核人，我想凭一个 run id 复现他人的结果。
- US-Q3：作为工程师，我想用 REST/WS API 拉取标的、K 线与指标。
- US-Q4：作为团队负责人，我想把策略、参数小表和结果归档到项目空间。
- **US-Q5**：作为研究员，我想把策略信号生成真实订单草稿，人工确认后发到券商，并自动带上策略标签，以便回测与真实表现对照。

**基金公司**

- US-F1：我想在同一页看到多个组合的持仓权重、行业暴露与基准偏离。
- US-F2：作为风控，我想做简化 VaR、回撤、相关性与压力测试。
- US-F3：作为合规，我想查到「谁在什么时候把评级从 A 改成 B」。
- US-F4：作为管理员，我想按组织/部门/组合隔离数据。
- **US-F5**：作为基金经理，我想把已授权账户的真实成交同步进组合视图，看策略假设与实际执行的偏差——但不要平台替我下单。

**投顾**

- US-A1：我想一屏看到所有客户的组合表现与偏离提醒。
- US-A2：我想一键生成季度报告。
- US-A3：作为合规岗，我想确保不匹配的产品不会被推荐且留有确认记录。
- US-A4：作为客户，我想通过只读链接看自己的组合，链接到期自动失效。
- **US-A5**：作为客户，我想**自己**授权券商让投顾看到我的交易数据用于报告，且随时可撤销；我不希望顾问能操作我的账户。

## 3. 产品定位与边界

### 3.1 定位

**「面向海外市场的用户授权型投研工作台」**：以多市场 L1 行情为入口，以 AI 冷静层、模拟执行、规则回放和复盘为闭环；**在用户明确授权自有券商账户后，把跨券商真实交易与真实成交分析接入同一闭环，并把同意、来源、变更与导出做成可审计证据**；平台是工具与数据分析提供方，**不是券商、不托管资金、不代客理财、不提供持牌投顾结论**。

### 3.2 北极星指标

- C 端：**周活跃闭环用户数**（一周内走完「看盘 → 分析 → 模拟/真实交易 → 复盘」至少一次）。
- B 端：**周活跃工作区数**（工作区内至少 3 名成员产生研究/策略/报告动作）。
- 实盘：**授权且完成过一次「下单 → 成交 → 复盘」的周活跃用户数**。

### 3.3 一套内核、五套视图、三种交付、一条实盘通道

```text
┌─ 视图层（5 套）
│  小白引导视图 | 交易员工作台 | 量化策略工作台 | 基金组合风险台 | 投顾客户台
├─ 能力层（可装配）
│  规则引擎 | 回放引擎 | 组合分析 | 报告生成 | 权限/审计 | API 网关 | 通知中心
│  ★ 券商授权网关 | ★ 订单安全层 | ★ 成交同步 | ★ 交易数据分析
└─ 内核层（唯一实现）
   行情门面（多源 failover + BYOK） | 标的/交易日历/复权 | AI 冷静层
```

### 3.5 全局红线（任何角色都不做）

1. **不做平台自有资金、资金归集、托管、代客理财**；券商 KYC 与适当性由券商负责。
2. **实盘必须用户本人显式 OAuth 授权**；默认模拟，任何情况下不得从模拟/AI 草稿静默升级为真单。
3. **AI 与策略信号不自动提交真实订单**；P4 若开「受控自动执行」须单独评审、默认关闭、可随时终止。
4. **投顾不代客户下单、不采集/存储客户券商凭证**；客户数据仅在客户本人授权下只读可见。
5. **不做 OMS/EMS、机构柜台、FIX 接入、清算、估值核算、监管报送**。
6. **不荐股、不输出买卖结论、不承诺收益**；不展示「跟投/复制交易/收益排行」。
7. 不做跟单社区、策略排行榜、信号会员。
8. 不做 Tick/L2 回测、全市场扫描、Python 自由代码 IDE。
9. 不自建双录/签字/适当性监管流程；投顾合规只做辅助与留痕。
10. 行情与交易数据转发不得绕开券商开放平台条款；如条款禁止第三方下单，降级为**仅分析模式**（D7）。
11. **不服务中国内地客户**：不提供面向境内投资者的买入/入金通道，境内研发/客服节点不得为境外券商交易系统提供指令相关支持；A 股仅作参考行情。
12. **不使用 IBKR TWS 非商业许可做第三方收费产品**；商业化须先取得券商机构授权。
13. **不把聚合商报送价当行情源**；证券主体匹配须解决 CUSIP / ISIN / FIGI 标识符授权，缺失字段不得伪造。
14. **真实客户数据默认不进入 AI 训练**（需单独明示同意）；不得用于营销宣传或跟投展示。
15. 前端新增页面遵守 **500 行上限**，逻辑下沉到 `src/lib/*`。

## 5. 分角色 PRD

### 5.1 小白用户 —— 看得懂、不迷路、不被吓

**目标**：让零基础用户在 3 分钟内完成一次有意义的看盘，并知道下一步该学什么/练什么。
**成功定义**：首次引导完成率 ≥ 60%；引导页到模拟练习点击率 ≥ 25%；风险提示阅读后 7 日回访提升。
**明确不做**：买卖建议、目标价、荐股榜单、自动跟单、**实盘下单**。

#### 5.1.1 信息架构


### 5.3 量化团队 / 公司 —— 数据可信、实验可复现、结果可交付

**定位收敛**：做**轻量策略工作台 + 数据/API 服务 + 受控执行**，不是 Quant IDE。
**成功定义**：任一 run id 可复现；API 有文档与限流；10 人团队空间无越权；真实成交可回灌策略对照。
**明确不做**：Python/脚本上传、全市场扫描、Tick/L2 回测、机器学习选股、无人值守自动交易（P4 受控模式除外）、策略排行商城。

#### 5.3.3 回测结果与免责规范

结果页首屏必须包含：指标卡（年化、最大回撤、夏普标注假设、胜率、盈亏比、交易次数）、假设区（数据版本、复权口径、成交价规则、佣金/滑点、样本内外切分）、局限区固定文案「历史规则回放不代表未来收益；小样本与过拟合风险由使用者自行评估」。禁止「稳赚/必胜/年化 X% 保证」。**真实执行对照页同样适用，且不得把真实收益用于营销。**

#### 5.3.4 性能预算

- 单标的日 K 回放 ≤ 5 秒（5 年数据）；小篮 5–10 只顺序执行；Worker 并发 1。
- API 默认 QPS 5 / 日 10,000 次；WS 按工作区计数封顶；交易类接口额外限流。
- 任何回测请求不得同步阻塞 Web 请求路径。

- [ ] API Key 吊销立即失效；超限 429；`trade:write` scope 需单独授权。
- [ ] 策略信号生成的真实订单带标签，可回溯到 run。
- [ ] 受控自动执行默认关闭，一键停止后无新订单。

### 5.5 投顾 —— 客户跟踪、报告沟通、适当性

**定位收敛**：客户组合跟踪 + 报告沟通 + 适当性辅助；**客户交易数据仅在客户本人授权下只读可见，投顾不得代客下单**。

### 5.6 实盘授权与交易数据分析（跨角色专项 · v1.1 新增）

> 本节是实盘的**唯一权威口径**。各角色章节只描述差异，不重复定义流程。
> 状态：**P2（只读同步）/ P3（下单）/ P4（受控执行）**；启动需法务/合规评审与券商条款复核。

#### 5.6.1 定位与模式

**BYOB（Bring Your Own Broker）**：用户本人在券商完成 KYC 与适当性，通过 OAuth/PKCE 授权平台访问其账户；平台提供下单工具与交易数据分析，**不持有资金、不代客操作、不做券商 KYC**。

| 模式 | 说明 | 默认 |
|---|---|---|
| `paper` | 本地/券商模拟盘 | **是** |
| `live-readonly` | 已授权，仅同步账户/持仓/成交，用于分析 | 授权后可选 |
| `live-trade` | 已授权 + 用户显式开启交易 + 双步确认 | 需额外开启 |
| `live-auto` | 受控自动执行（P4） | **关闭**，需独立评审 |

#### 5.6.2 授权链路（复用现有 OAuth 基建）

```text
设置页 /settings/broker
   ↓ 用户阅读《实盘授权与风险告知》并勾选
/api/oauth/{broker}/start （已有：state + PKCE）
   ↓ 跳转券商授权页（scope 最小化：行情只读 / 账户只读 / 交易，分开申请）
/api/oauth/{broker}/callback （已有：校验 state、换 token、加密落库）
   ↓ BrokerConnection 记录 scope / 授权时间 / 到期时间 / 撤销入口
账户选择页：展示券商返回的账户列表（明确标注模拟/实盘、尾号）
   ↓ 用户明确选择，禁止静默选实盘账户
连接完成 → 默认 live-readonly；如需交易再单独开启 live-trade
```

**要求**

- Token 与 refresh token 使用现有 `encryptJson` 加密存储，不明文落库、不进日志。
- Scope 分离：只读连接**不得**获得交易权限；交易 scope 需二次授权。
- 用户可在设置页一键断开；断开后券商侧授权同时提示用户可撤销（平台不替用户撤销）。
- **券商优先级（海外口径）**：① 长桥（OAuth 2.1、已实现）→ ② 老虎（个人 OAuth2；机构仅签名认证）→ ③ Schwab（标准 OAuth2，品种有限）→ ④ IBKR Client Portal（须先谈商业授权）。富途/moomoo 作亚太补充。**A 股交易不纳入首版**；加密独立评估。
- **聚合层并行**：SnapTrade 做广度（40+ 券商、约 16 家可下单，仅实时档）与 Plaid 做美国覆盖（只读）；生产接入须先拿到书面报价。不自建数百条券商连接。
- **IBKR TWS API 为非商业许可**，不得用于第三方收费产品；以机构商业授权为前提，否则只接 Client Portal 并遵守其条款。
- 聚合商报送价只用于校验数量，**估值用自有行情重算**；证券主数据须覆盖 CUSIP / ISIN / FIGI，无授权时标注缺失而非伪造。
- **券商条款若不允许第三方下单，降级为仅分析模式（D7）**；任何辖区均不依赖强制开放 API 法规。

#### 5.6.3 下单安全（P3）

**双步确认流程**

1. **草稿**：来自手动表单 / AI 情景 / 策略信号；只预填，不提交。
2. **预览**：账户尾号、标的、方向、数量、价格类型与价格、预估金额、佣金/汇率估算、数据源与时间。
3. **确认**：用户显式点击「确认下单到券商」；可配置二次确认短语。
4. **提交**：带 `clientOrderId` 幂等键；超时**只查询不重发**。
5. **回执**：券商订单号、状态、时间；失败原因原样展示，不美化。
6. **审计**：全过程写入 `AuditLog`（人/账户/标的/数量/价格/幂等键/请求与响应摘要）。

**硬规则**

| 规则 | 说明 |
|---|---|
| 默认模拟 | 任何入口默认 `paper`；实盘徽标常显且不可关闭 |
| 无自动提交 | AI 草稿、策略信号、回测结果一律只生成草稿 |
| 账户校验 | 下单前校验账户归属与模式；非本人账户拒绝 |
| 硬风控闸 | 单笔名义上限、日内亏损上限、最大持仓比例、禁市价（可配）、交易时段校验、标的白名单（可选） |
| 软提示 | 集中度偏高、临近财报、连亏后加仓；提示不阻断但记录 |
| 幂等 | 每笔唯一 `clientOrderId`；重试查询不重下 |
| 撤改单 | 二次确认；当日撤单次数上限 |
| Kill switch | 一键断开授权并停止所有实盘动作；历史数据保留 |
| 数据标注 | 所有真实数据标注券商、账户尾号、同步时间 |

#### 5.6.4 交易数据分析（P2 基础版 / P3 完整版）

**数据来源**

1. 券商 API 同步（订单、成交、持仓、资金流水）— 优先。
2. 用户上传对账单 CSV — 券商不支持 API 时的保底（D7）。
3. 平台模拟盘 — 作为对照基准，不混入真实数据。

**统一记录**：`TradeRecord` = 券商 + 账户 + 订单 + 成交 + 费用 + 汇率 + 时间戳 + 策略标签 + 计划标签。

**分析维度**

| 类别 | 指标 |
|---|---|
| 结果 | 已实现/未实现 PnL、胜率、盈亏比、平均盈利/亏损、平均持仓时长、最大回撤、手续费占比 |
| 过程 | 计划执行率（订单是否挂规则标签）、止损执行率、复盘完成率、情绪标签分布 |
| 行为偏差 | 追高（买入价距当日高点）、报复交易（连亏后 30 分钟内下单）、过度交易（日内笔数超阈值）、集中度过高 |
| 对照 | vs 基准、vs 模拟盘同期、vs 策略规则回放（成本/滑点/时点偏差） |
| 时间 | 按日/周/月、按标的、按策略、按情绪标签切片；**按市场时区归一，不按浏览器时区** |
| 税务与成本基础 | 多币种折算（交易币种 / 账户币种 / 报表币种）、成本基础与税批（provider 供给时）、手续费与汇兑损益拆分 |
| 执行质量 | 滑点、时点偏差、venue/broker 对比的**基础指标**；作为 EU 最佳执行举证的内部证据，不宣称「最佳执行」结论 |
| 合规证据 | 同意链路（取得/撤回/版本）、数据血缘、导出快照与保留期；供 SEC 17a-4 / Reg S-P、HKIDR、MAS 检查使用 |

**AI 复盘约束**：只输出行为模式与规则调整建议草稿；不输出「应买/应卖/目标价」；每段输出标注数据时间范围与来源；用户可关闭 AI 解读而只看确定性统计。

**对账**：平台记录 vs 券商流水差异提示，**不自动修正**；用户确认后才更新；差异事件入审计。

**隐私与合规**：默认仅账户所有人可见；团队/投顾场景需数据所有人显式授权；导出带水印与审计；**真实收益不得用于营销宣传或跟投展示**。

| FR-L16 | 实盘埋点 | P2/P3 | `broker_connected` / `scope_granted` / `live_order_previewed` / `live_order_submitted` / `trade_data_synced` / `broker_disconnected` | **不上报**金额、持仓、账户尾号原文 |

#### 5.6.6 合规边界

| 我们做 | 我们不做 |
|---|---|
| 用户本人 OAuth 授权、工具型下单、成交同步、行为分析 | 平台资金、托管、代客理财、跟投、复制交易 |
| 展示券商返回的账户与成交数据，标注来源 | 替券商做 KYC / 适当性判定 / 双录 |
| 规则化硬风控与风险告知 | 投资建议、收益承诺、荐股信号 |
| 用户可撤销、可导出、全审计 | 客户凭证采集、投顾代客操作、机构柜台接入 |
| 条款不允许时降级为仅分析 | 规避券商开放平台条款转发数据 |
| 跨券商只读聚合 + 可审计的过程/合规证据 | 读单一券商账户的通用看板（券商 MCP 已免费提供） |
| 明示同意台账、区域数据平面、可退出与留存策略 | 把客户数据用于 AI 训练、营销或跟投展示 |
| 按目标辖区注入 Reg BI / MiFID II / HKIDR / MAS 文案 | 替持牌人做适当性结论、双录或监管报送 |

#### 5.6.7 验收清单

- [ ] 未勾选风险告知无法进入 OAuth；只读 scope 无法调用交易接口。
- [ ] 下单必经预览与显式确认；AI/策略草稿无一键直达真单路径。
- [ ] 重复提交同一 `clientOrderId` 不会重复下单；超时只查询。
- [ ] 硬风控触达时阻断并给出明确原因；Kill switch 后无新订单。
- [ ] 成交同步带券商/账户/时间标注；差异需确认，不自动修正。
- [ ] 交易分析不含买卖建议；真实收益未出现在营销页。
- [ ] 投顾端无客户账户下单入口；客户授权可撤销且立即停止同步。
- [ ] 法务/合规签字与券商条款复核记录归档。

### 6.1 权限模型总览

```text
User ──< Membership >── Workspace ──< Project / Portfolio / ClientGroup
  │
  └─< BrokerConnection >── BrokerAccount（归属 User，非 Workspace）
                              │
                              └─ 只读授权可授予他人；交易权限永远属于账户所有人

角色：owner | admin | researcher | pm | risk | compliance | advisor | viewer
数据范围：organization → department → portfolio → client → brokerAccount
原则：服务端强制（deny by default）+ 前端只做呈现隐藏 + 越权必记审计
```

### 6.2 审计事件最小集

| 类别 | 事件 |
|---|---|
| 账户 | 登录、角色变更、API Key 创建/吊销 |
| **券商** | **授权发起/完成/拒绝、scope 授予、账户选择、断开、token 失效** |
| **交易** | **订单预览、提交、撤单、改单、成交同步、对账确认、风控触达、Kill switch** |
| 策略 | 创建、版本更新、run 执行、结果导出、分享、信号生成草稿 |
| 研究 | 评级变更、审批通过/退回、标的池调整 |
| 组合 | 组合调整草稿、风险阈值变更、授权账户数据同步 |
| 客户 | 档案变更、报告生成/发布/分享、适当性覆盖、**交易数据授权/撤销**、沟通记录 |
| 管理 | 权限变更、模板变更、导出、白标配置变更 |

每条审计记录至少：`actorId` / `workspaceId` / `action` / `targetType` / `targetId` / `before` / `after` / `ip` / `createdAt`。**交易类审计另含 `brokerAccountId` / `clientOrderId`，但不含凭证与完整账户号。**

### 6.3 合规文案与敏感词

- 文案中心提供四组：`disclaimer`（按角色/地区）、`riskHint`（分级）、`forbiddenWords`（报告/沟通扫描）、`liveRiskNotice`（实盘授权与下单前告知）。
- **地区包**：US（Reg BI / Reg S-P / 记录保存）、EU-UK（MiFID II 最佳执行 / DORA / 研究解绑）、SG（MAS 数字顾问与 FAA-N25 留存）、HK（SFC 1/4/9 号牌边界与 HKIDR 明示同意）。按用户辖区注入，不默认套用美国口径。
- AI 输出、用户发布内容、实盘预览页统一过扫描；命中提示但保留人工判断（明显违法词直接阻断）。
- 所有免责链接指向 `/disclaimer`；白标部署可配置但不可删除，尤其**实盘风险告知不可移除**。

### 6.4 API 设计原则

- 版本前缀 `/api/v1`；资源命名复数；分页游标；错误码稳定。
- Scopes：`market:read`（默认）、`account:read`、`trade:read`、`trade:write`（单独申请）、`workspace:admin`。
- 写接口仅限草稿/配置类与用户授权下的交易类；不开放机构柜台或代客接口。
- 所有响应带 `dataSource` / `asOf` / `datasetVersion`；交易响应另带 `broker` / `clientOrderId`。
- 限流：QPS + 日配额双维度；429 带 `Retry-After`；Key 级日志保留 30 天。

### 6.5 实时性与流量治理（针对当前流量瓶颈）

| 角色 / 场景 | 默认更新频率 | 通道策略 |
|---|---|---|
| 小白 | 30–60s | 轮询；不默认订阅 WS |
| 交易员 | 3–5s（关键标的） | WS 订阅 + 引用计数；仅订阅可见标的 |
| 量化 API | 按需 | REST 快照 + 显式 WS 订阅；QPS 限流 |
| 基金 / 投顾 | 快照 + 手动刷新 | 默认不开 WS；报告用定时快照 |
| **券商成交同步** | **10–60s 增量轮询 / Webhook（券商支持时）** | **独立 Worker；不与行情 WS 混流；不推送逐笔行情** |

治理要求：

1. WS 订阅按 `workspaceId` 与可见标的引用计数，离页即退订。
2. 增量推送（delta）优先，禁止全量报价帧。
3. 断线指数退避重连；超阈值降级轮询并在 UI 标注。
4. 每工作区连接数与消息速率上限可配置；超限拒绝并告警。
5. 建立流量看板：按角色/工作区/标的统计字节数，支撑计费与降级决策。
6. **实盘数据同步独立配额**，不得因行情流量高峰延迟订单状态更新。

### 9.2 统一事件规范

- 事件名：`{role}_{action}_{object}`，如 `guide_complete_onboarding`、`qa_run_reproduce`、`live_order_submitted`。
- 公共属性：`userId`（匿名时 hash）、`workspaceId`、`role`、`viewMode`、`locale`、`timestamp`。
- **禁止上报**：客户姓名、持仓明细原文、账户尾号原文、金额、券商 Token、问卷答案原文（只报等级）、API Key。
- 实盘事件只记录动作与状态，不记录交易内容；交易内容留在服务端审计。
- 所有事件先落本地队列，失败重传；不得阻塞主路径。

### 10.1 风险登记

| 风险 | 等级 | 影响 | 缓解 |

| **海外多辖区合规** | **高** | Reg BI / Reg S-P / MiFID II / DORA / HKIDR / MAS 口径不一 | 首版锁定 1–2 辖区；地区包 + 同意台账 + 区域数据平面；法务签字前置 |

## 13. 海外市场竞品、合规与实施成本（v1.2 新增）

### 13.1 目标市场与客群

- **C 端**：美国/加拿大自助投资者、新加坡/中国香港及亚太海外华人；小白与交易员共用同一产品。
- **B 端**：独立投顾工作室（RIA / IAR / EAM）、家族办公室、小型资管与量化团队；基金公司/投顾均按**海外持牌主体**理解，适当性结论由持牌人承担。
- **明确排除**：中国内地客户。2026 年八部门整治方案下，境外机构不得为存量境内投资者提供买入与转入；境内研发/客服为境外券商交易系统提供指令相关支持也在监管射程内。A 股行情仅作参考数据。
- 首版建议锁定 **1–2 个辖区**（美国 + 新加坡/中国香港），欧盟后置到 P2 之后。

### 13.2 竞品格局（四层，不存在完全同款）

| 层 | 代表 | 已验证的能力 | 缺口（我们的空位） |
|---|---|---|---|
| 券商自建 MCP / AI | IBKR、Robinhood Agentic Trading、Webull、长桥 OAuth 2.1（100+ 工具）、老虎、富途/moomoo | 免费读自己账户、持仓与成交、AI 起草但人工批准 | **只看自家账户**，无跨券商、无跨资产/跨实体、无纪律分析 |
| 聚合 API | SnapTrade（40+ 券商、约 16 家可下单，$100/月 + $1–2/用户/月）、Plaid Investments（约 3,200 家，只读）、Yodlee、Akoya、MX、Wealthica | 跨券商连接是刚需，已有成熟供应链 | 只返回数据，不做行为分析；亚太覆盖薄；标识符授权不足 |
| 投顾/资管 TAMP/PMS | Addepar（$9T+ 平台资产）、Orion（$5.9T）、Envestnet Tamarac、老虎 TradingFront、富途大象财富 | 组合会计、报表、顾问工作流已被验证 | 重、贵、面向机构；没有面向 C 端的过程纪律叙事 |
| 交易复盘 Journal | TradeZella、TraderSync、Tradervue、TradesViz（约 $15–80/月） | 多账户复盘、模式识别、付费意愿明确 | **只服务交易员单点**，不做小白/量化/基金/投顾；以美股为主 |
| 机构 TCA | Bloomberg BTCA、TT TCA（年处理约 $50T 本金） | 最佳执行举证是合规刚需 | 机构级门槛，无零售/顾问自助版 |

**结论**：市面上没有「跨券商 + 五角色 + 授权真实成交 + 可审计合规证据」的同款。最接近的是「券商 MCP + trading journal」的组合，但两者分别占据账户侧与复盘侧，中间没有产品把跨券商数据与多角色工作流打通。

### 13.3 差异化打法

1. **不做「读自己账户」的通用看板**——那是券商免费 MCP 的主场，正面竞争必输。
2. **楔子 = 跨券商统一视图 × 行为纪律分析 × 合规证据 × 多角色视图**：把已被验证的 journal 能力（行为模式、复盘）放到跨券商数据上，再叠加同意/血缘/留存的可审计能力。
3. **最易付费的是合规证明，不是洞察**：EU 2026/825 把最佳执行从公开披露改为常设内部举证；Reg S-P 把 72h/30d 通报变成硬链路；HKIDR 把明示同意变成可被检查的功能。这些是可定价的功能点。
4. 不碰组合会计、税务申报、OMS/EMS、最佳执行结论；这些是 Addepar / Orion / Bloomberg 的护城河。

### 13.5 实施成本（基于当前仓库实测）

**已有地基**：`src/` 共 **13.8 万行 / 878 个文件**（TS 6.8 万 + TSX 6.7 万 + CSS 0.3 万），另有 10 个语言包 **2.8 万行**，前端相关基线合计约 **16.6 万行**；78 个 API 路由、32 个页面、338 个组件、33 个 Prisma 模型。`src/lib/market` 约 1.35 万行、`lib/strategy` 2288 行、`lib/trading` 1162 行；OAuth/PKCE + AES-256-GCM 凭证已落地；`BrokerGateway` 接口已定义（`getBrokerGateway()` 目前恒返回 `null`）。**全仓仅 1202 行测试、14 个文件超过 500 行**——测试覆盖是后续代码量膨胀的隐藏项。

| P4 受控自动执行（增量） | +80–150 人日 |

按 1 人全职约 **8–14 个月**到 P2；多人并行可压缩日历时间但不降低总人日。**代码行数不是主要成本**：海外定位新增的复杂度集中在多币种/多时区、券商条款与标识符许可、同意与留存链路、跨券商字段口径、区域数据平面。最大的不确定性（聚合商生产报价、券商条款、法务辖区矩阵）不消耗人日但消耗日历时间，必须在写上线日期前拿到书面结论。

### 13.6 决策建议

1. **先花 2–3 周锁定辖区与聚合商**，拿到生产报价和律师意见，再承诺 P1 日期。
2. **先做只读分析 MVP**（P0 + P1-a 子集）：跨券商持仓/成交统一视图 + 行为纪律复盘，不开放下单——用真实用户验证「跨券商分析是否付费」。
3. **直连做深度、聚合做广度**：长桥/老虎直连拿完整字段，SnapTrade/Plaid 覆盖其余券商；不自建数百条连接。
4. **把合规证据当卖点打包给顾问机构**，而不是当成本中心；这也是与 trading journal 拉开差距的地方。

### 13.7 前端单仓库容量评估（v1.2 补充）

**问题**：92 条 FR 若全部按现状的 Next.js 单仓库、单 `src/components` 树落地，前端代码会到多少？单仓库撑不撑得住？

#### 13.7.1 基线拆解（实测口径）

| 指标 | 现在 | 全量落地 |
|---|---:|---:|
| 页面 `page.tsx` | 32 | 70–90 |
| API 路由 `route.ts` | 78 | 130–160 |
| 组件 `.tsx` | 338 | 600–800 |
| `src` 文件数 | 878 | 1,500–2,200 |
| 单语言 i18n 键（按行数折算） | 约 2,800 | 6,000–9,000 |
| 超过 500 行的文件 | 14 | 需持续压制（§3.5 红线 15） |

#### 13.7.4 结论：不必拆仓库，但必须拆边界

Next.js 单仓 30 万行级**在工程上可行**（业界有 50 万行级单仓先例），行数本身不是硬上限。真正的风险是**耦合形态**：`src/components/symbol` 已是「页面内聚」而非「可复用组件」，若五套角色视图都往同一棵 `components` 树里塞、靠 `if (viewMode)` 分支分流，会迅速变成不可维护的条件迷宫。

**出现以下任一信号才拆仓**（量化触发线）：

1. 全量 `next build` > 10 分钟，或 `tsc --noEmit` > 90 秒且持续优化无效；
2. 单个 PR 平均触碰 > 15 个 feature 目录，评审无法按域分工；
3. 两个以上团队需要**独立发布节奏**（如 C 端周更、B 端月更）；
4. 私有部署客户要求「只交付部分模块源码」，单仓无法裁剪授权范围。

**在触发线之前，只做逻辑分区，不做物理拆分**：

```text
同一个 Git 仓库（保持 pnpm / 单 CI）
src/
  app/
    (marketing)/          营销、定价、免责
    (c-end)/              C 端共用路由，viewMode 在布局层注入
    (workspace)/[id]/     B 端命名空间，独立租户上下文
    api/v1/               开放 API
  features/                ★ 新增代码一律按域放，不再堆进 components/
    guide/ trader/ strategy-lab/ advisor/ portfolio/ evidence/ broker/
  lib/                     共享内核（行情/标的/AI/规则/交易/合规）
  components/ui/           设计系统（现有 2,236 行，保持无业务态）
messages/                  单一语言包源，禁止按角色复制
```

**明确不要做的三种拆法**：

- **不要按五个角色建五个前端仓库**：共享内核会漂移，10 语 i18n 与合规文案会分裂成 5 份，Reg S-P / HKIDR 的「一处修改全站生效」直接失效。
- **不要把 `viewMode` 分支塞进现有 symbol 组件**：该模块已 2.7 万行，应在 `features/guide` 与 `features/trader` 各写薄视图层，共享 `lib` 与 `components/ui`。
- **不要在无付费试点时提前把 B 端拆成独立应用**：只是多一套 CI、多一份语言包，没有收益。

若真到拆仓那天，用 **Turborepo + pnpm workspace 拆 3 个 app + 2 个 package**（`ui` / `core`），而不是 5 个独立仓库；语言包与合规文案始终保留单一数据源。
