# 个股页 · 交易员视角评估

> 视角：有实盘经验的交易员，第一次打开 `/symbol/stock/AAPL` 会怎么判断这个工具
> 评估日期：2026-10-27
> 依据：`src/components/trading/*`、`src/lib/trading/*`、`src/lib/market/session.ts`、`src/lib/format-number.ts` 代码审查
> 综合评分：**6.5 / 10**（分口径：下单执行 5.5 / 交易纪律 8.0）

---

## 一句话结论

**这是一个"逼你别乱下单"的工具，不是一个"让你下得快"的工具。**

它对交易纪律的理解（失效价、情绪自检、日亏损熔断、策略归因、成交回标到 K 线）明显高于普通零售产品；但把它当交易终端用，票面上缺了交易员认为理所当然的一半要素——费用、有效期、单位、二次确认、货币、持仓浮盈。

如果这是个"复盘 + 模拟练习"产品，6.5 偏低；如果按"我在这个界面下单"的标准，5.5 算给面子。

## 三、从"想法"到"成交"要几步

实测路径（`symbol-quote-bar.tsx` → `symbol-dock-drawers.tsx` → `trade-panel.tsx`）：

1. 报价条点「交易」→ 抽屉打开（1 击）
2. 方向已默认 buy，类型默认 market
3. 数量默认 `"1"`，需手改
4. 点「Buy」提交（1 击）

**理论最少 3 击，这点是合格的**，比多数需要"先登录→进交易页→选账户→填单"的产品快。

但交易员的真实动作不是"买 1 股"：

| 真实动作 | 现状 |
|---|---|
| 买可用资金的 25% | ❌ 只能手算再输入 |
| 平掉现有持仓 | ❌ 要手动切 sell + 手输数量；没有「平仓」按钮 |
| 反手（平多开空） | ❌ 不支持（产品明确 long-only） |
| 改价追单 | ✅ 点 bid/ask 自动填限价并切到 limit |
| 撤单 | ✅ 票面下方 open orders 直接撤 |

**最刺眼的一条：持仓只在票面显示"数量 + 均价"，没有"市值 / 浮盈浮亏"。** 交易员下完单第一眼要看的是"这单现在赚多少"，而这里要跳到 `/portfolio` 才能看到。`TradeAccountStrip` 的注释写着"只展示本票持仓"，这个取舍在执行效率上是负分。

## 四、票面完整性对照

交易员心里的标准票面 vs 现状（`trade-panel.tsx`）：

| 要素 | 现状 | 评价 |
|---|---|---|
| 方向（买/卖） | ✅ Segmented，红绿区分 | 好 |
| 委托类型 | ✅ 市价 / 限价 / 止损 | 够用，缺止损限价（stop-limit） |
| 数量 | ⚠️ 裸数字输入，`step="any"` | 无整手校验、无最小变动单位、无单位标注（股/手/张） |
| 价格 | ✅ 限价与止损价分字段 | 好 |
| 盘口填价 | ✅ 点 bid/ask 直接填 | 好，是专业票面的做法 |
| 预估金额 | ⚠️ 有，但 **硬编码 `$`** | A股/港股金额显示错误 |
| 手续费 / 佣金 / 税 | ❌ 完全没有 | 模拟收益系统性高估 |
| 有效期（TIF） | ❌ 没有 | 只有当日/立即，无法挂 GTC |
| 可用资金 | ⚠️ 有 Buying power 展示，但提交前不做上限提示 | 超额只能等后端 `INSUFFICIENT_CASH` 报错 |
| 二次确认 | ❌ 单击即成交 | 模拟盘可容忍，但与真实操作习惯相反 |
| 失效价（invalidation） | ✅ 可填，且进风险快照 | **很好，多数产品没有** |
| 情绪自检 | ✅ 必选标签 | 强制冷静，产品灵魂 |
| 策略归因 | ✅ 可绑 strategyId | 好 |

票面 11 项里，**4 项缺、3 项有瑕疵**。这是 5.0 分的来源。

## 五、数据可信度：交易员最先看、这里最弱

### 5.1 实时状态不可见

`use-symbol-page.ts` 算出了 `wsConnected / wsDegraded / wsPush`，并据此决定轮询 60s 还是 5s，但没有任何 UI 呈现。

交易员看到 210.35 这个价，无法判断：

- 是 WebSocket 推的？
- 还是 5 秒轮询的？
- 还是连接早就断了、这是个几分钟前的死价？

**这是"能不能用于决策"的分水岭。** 一个不知道数据新鲜度的报价，交易员不会用第二次。

### 5.2 时间戳无时区

`format-number.ts:14` 的 `formatTime` 用浏览器本地时区 + 固定 `en-US`，不带任何时区标识。

美股在 A股 用户的屏幕上显示 `21:35`，没有 ET 后缀，也没有"北京时间"说明。港股、A股、美股、加密四个市场混在同一个站里，这个歧义每天都会出现。

### 5.3 精度不按市场自适应

| 位置 | 现状 | 后果 |
|---|---|---|
| `symbol-rail-depth.tsx` `fmtPx` | 固定 2 位小数 | 加密小币种（0.00001234）显示成 `0.00`，盘口全废 |
| `trade-panel.tsx` `fmtMoney` | 固定 2 位 | 港股仙股（0.001）精度丢失 |
| `format-number.ts` `formatPrice` | 默认 6 位 | 只有图表用，票面不用 |

同一只标的，图上是 6 位精度、票面是 2 位、盘口是 2 位。**交易员会认为这是三个不同的数。**

### 5.4 交易日历缺失

`src/lib/market/session.ts` 开头明写：

```ts
/** Equity regular-session helpers (no holiday calendar — weekends + clock only). */
```

也就是说 A股国庆、美股感恩节、港股佛诞，系统都认为"开市中"。图表里用的 `liveSession` 因此会在节假日继续按盘中处理。

## 六、多市场适配：三个硬伤

### 6.1 货币符号硬编码

```tsx
// trade-panel.tsx:413
<span className="aw-metric-value">${fmtMoney(estimate)}</span>

// trade-account-strip.tsx:35
{avgCost != null ? `$${fmtMoney(avgCost)}` : "—"}
```

买 10 手 A股（CNY），预估金额显示 `$12,345.00`。这是**交易员一眼就会截图发群里的错误**。

`paperAccount.currency` 字段存在（默认 `"USD"`），但从没被用来决定符号。

### 6.2 单一美元现金池，跨市场不折算

`prisma/schema.prisma`：

```prisma
model PaperAccount {
  cashBalance Decimal @db.Decimal(18, 4)
  currency    String  @default("USD")
}
```

一个 `cashBalance` 服务所有市场。买 A股扣的是美元数字，买美股也扣同一个数字，**没有任何汇率折算**。

后果：跨市场组合的净值、收益率、风险占比全部失真。交易员做多市场配置时，这个账户没法用。

### 6.3 无手续费，模拟收益系统性偏高

`src/lib/trading/execute.ts`：

```ts
const notional = qty * fillPrice;
if (side === "buy") {
  if (cash + 1e-8 < notional) throw new TradingError("Insufficient cash", ...);
  await tx.paperAccount.update({ data: { cashBalance: cash - notional } });
```

成交价 = 委托价，**没有滑点；没有任何佣金、印花税、交易征费**。

交易员算过账就知道：A股 双边约 0.1%（含印花税），港股双边约 0.2%，美股按笔。一个 20 次/月的策略，零成本与真实成本之间能差掉年化 2–5 个百分点。**这个模拟账户跑出来的"盈利策略"，拿到实盘可能是亏的。**

对一个主打"记录与复盘"的产品来说，这不是小事：**复盘结论被一个不存在的成本环境污染了。**

## 七、交易员会点头的三件事

必须说清楚，这个产品有真正懂交易的人在思考：

### 7.1 强制写"失效价"

票面上有一个 `Invalidation price`（"Optional plan break level"），并进入 `riskSnapshot` 落库。

这等于每次下单都被问一句：**"什么情况下你承认自己错了？"** 这是专业交易与赌的分界线。绝大多数零售产品不做这件事。

### 7.2 日亏损熔断

`paperAccount.dayStartEquity + dayStartDate`，配合 `checkOrderRisk` 的 `dayPnlPct`：

```ts
/** Day P/L % vs dayStartEquity; null if unknown. */
dayPnlPct: number | null;
```

**这是真实交易台的日常风控**（日内亏损超阈值强制停手），散户工具里几乎见不到。

### 7.3 成交点回标到 K 线

`candle-chart-trade-markers.ts` 的 `syncTradeMarkers` 把用户自己的成交打进图表。

复盘时能直接看到"我在这根 K 线的什么位置进的、什么位置出的、后面走势如何"。**这是把交易记录和价格行为绑在一起的最有效方式**，也是这个产品最值得讲的差异化。

### 附加：风险门禁是"软/硬可切换"的

`RiskCheckResult` 有 `softWarnings` 与 `ok: false` 两档，`softOnly` 配置决定违规是警告还是拦截。这个设计比"一刀切禁止"更接近真实风控台的用法。

## 九、结论：它是什么

**它不是交易终端，是交易日记的延伸。**

- 如果你是来做"执行"的：缺费用、缺单位、缺 TIF、货币显示错误、看不到实时状态——**6 分以下，不建议用**，任何一家券商的 App 都比它强。
- 如果你是来做"练习与复盘"的：它有失效价、情绪自检、日亏熔断、策略归因、成交回标、风险快照落库——**这是市面上少见的、真按交易纪律设计的产品**，8 分。

所以 6.5 这个总分其实说明了一件事：

> **产品的"思想"比"手艺"领先。**
> 它想清楚了交易员该被怎么约束，但还没做完交易员需要怎么被服务。

如果只让我改三处，按顺序是：

1. **货币符号**（0.5 天，把一个会被截图的 bug 修掉）
2. **手续费**（2 天，让复盘结论站得住）
3. **实时状态 + 时区**（1 天，回答"这个价能不能信"）

这三处做完，分数会到 7.5；再把浮盈浮亏与一键平仓补上，就是 8.0——那时它配得上"给交易员看"这五个字。
