# Q-Stock 产品留存、品牌与推广计划

> 目的：把现有的行情、研究、AI、模拟交易和复盘能力串成可持续使用的 C 端产品，并建立清晰、可信、可传播的品牌。  
> 定位基线：个人投资者的多市场学习型投研终端；帮助用户形成研究与复盘习惯，不提供收益承诺或喊单服务。  
> 本文是验证计划，不代表所有功能均已上线。实施优先级应与[可落地路线图](./product-roadmap.md)协调。

## 1. 产品判断

Q-Stock 不应只做另一个行情聚合页，也不应把核心价值简化为 AI 问答次数。更有机会形成差异化的主张是：

> **帮助个人投资者把关注、研究、模拟和复盘连成一个可持续的过程。**

核心产品闭环：

```text
关注标的 → 记录研究问题与假设 → 追踪重要变化 → 模拟验证 → 周期复盘
```

目标不是让所有用户每天打开，而是在用户关注的标的或研究计划发生重要变化时提供可靠的回访理由，并让用户回来后能接着上次的进度继续。

## 2. 用户价值与可做能力

| 能力方向 | 产品体验 | 复访价值 | 建议阶段 |
|---|---|---|---|
| 研究卡片 | 每个自选标的可记录关注理由、待验证问题、观察条件、风险点和复查日期 | 形成个人研究资产，不必每次从头开始 | P0 |
| 自选变化摘要 | 汇总自选标的的价格提醒、重要新闻、财报或用户设定条件变化；注明来源、时间和数据限制 | 有变化时回看自己的研究，而非刷泛资讯 | P0 |
| 研究版本与变化对比 | 保存每次分析；再次分析时比较新旧数据、假设和结论，突出需要重新检查的部分 | AI 从一次性回答变成持续研究工具 | P1 |
| 计划关联模拟交易 | 模拟下单前记录计划、风险和失效条件；成交后记录实际执行与偏差 | 把“当时怎么想”与结果连起来 | P1 |
| 周度 / 月度复盘 | 汇总模拟交易、提醒、计划执行、情绪标签和重复出现的问题 | 建立固定的复查节奏，体现长期进步 | P1 |
| 规则实验室 | 用透明、有限的规则模板进行历史回放，再关联模拟练习；披露假设和局限 | 串起学习、实验、练习与复盘 | P2 |
| 学习任务与工具练习 | 短文后直接完成仓位、定投、复利等练习，或在模拟盘验证理解 | 从阅读转到实际练习 | P1 |

### 建议的研究卡片字段

- 关注原因：为什么把它加入自选？
- 研究问题：现在最想弄清楚什么？
- 观察条件：哪些公开信息或价格变化值得回看？
- 风险与失效条件：什么情况会让原来的假设不再成立？
- 复查日期：下次主动复查的时间。
- 资料与记录：关联新闻、财报、AI 分析、模拟交易和个人笔记。

这些内容应由用户创建和控制。AI 可帮助整理和比较，但不能把模型生成的内容伪装成事实、自动替用户下单或作个性化买卖承诺。

## 3. 留存体验设计

### 3.1 形成健康的回访节奏

按使用动机提供选择，不用“所有人每日打开”作为产品目标：

- **主动观察型**：用户自己设定的价格或研究条件触发后回访。
- **长期研究型**：财报、重要信息变化或用户设置的复查日期到来时回访。
- **学习型**：每周完成一项短阅读、工具练习或模拟复盘。

提醒必须可解释、可关闭、可调整频率；优先服务用户事先定义的关注条件，不使用制造焦虑的泛推送。

### 3.2 主回访闭环

1. 新用户选择少量自选标的，并写下关注原因或研究问题。
2. 用户选择提醒方式、频率和复查日期。
3. 平台仅在符合条件时提供摘要，标明来源与时间。
4. 回访后先展示“自上次查看以来的变化”，再链接至原研究卡、AI 分析或原始资料。
5. 用户更新假设，或创建模拟计划。
6. 每周回顾研究记录与模拟执行，给出下一步可选行动。

### 3.3 减少打扰与建立信任

- 默认提供低频、摘要式通知；由用户主动选择开关和渠道。
- 区分事实、数据源信息、模型分析和用户个人判断。
- 展示数据时间、可用性与已知限制；源失效时明确说明，不展示成功形态的空结果。
- 提供暂停、退订、静默时段和删除个人记录的入口。
- 不用收益排名、倒计时、恐惧或“错过机会”文案促活。

## 4. 品牌建设

### 4.1 品牌基础

| 项目 | 建议 |
|---|---|
| 品牌名称 | Q-Stock / 钱力股（对外按目标市场统一使用名称与拼写） |
| 品类 | 面向个人投资者的学习型投研终端 |
| 核心承诺 | 让研究有记录、变化有依据、复盘有积累 |
| 差异化 | 多市场工作台 + 冷静分析 + 模拟练习 + 过程复盘，而不是喊单或单纯行情流 |
| 品牌性格 | 冷静、诚实、清晰、实用、有边界 |
| 品牌口号候选 | **看清变化，留下判断。** |

口号是候选文案，正式使用前应通过目标用户访谈和小规模页面测试验证。

### 4.2 品牌使命与定位文案

- **使命**：帮助个人投资者把市场观察转化为有记录、可练习、能复盘的研究过程。
- **愿景**：让投资者更重视自己的判断流程，而不是追逐下一条所谓确定性信号。
- **一句话介绍**：Q-Stock 是一个多市场学习型投研终端，帮助你管理自选、研究变化、进行模拟练习并复盘过程。
- **10 秒介绍**：不只看行情，也把研究和复盘留在同一个工作台。
- **30 秒介绍**：Q-Stock 面向关注美股、港股、A 股和加密资产的个人投资者，把自选、行情、AI 辅助研究、模拟交易和复盘连在一起。它帮助你记录为什么关注、后来发生了什么、计划是否执行；不承诺收益，也不替你做投资决定。

### 4.3 语气与内容边界

**应该这样表达**

- “以下是可能情景与需要核对的假设。”
- “数据截至……；该来源可能延迟或缺失。”
- “你可以把这个条件加入观察清单。”
- “历史回放用于学习，不代表未来表现。”

**避免这样表达**

- “稳赚”“必涨”“抄底信号”“AI 告诉你该买什么”。
- 把相关性、预测或模型输出包装成确定事实。
- 不披露来源、时间、局限的“实时”“专业级”宣传。
- 用收益截图或个案暗示普遍收益。

品牌每项对外主张都应有产品证据支持：支持哪些市场、行情更新时间、AI 能力边界、回放假设、数据许可范围均需可核实。

### 4.4 视觉与体验一致性

- 延续现有产品的专业、克制、清晰风格；先完善现有视觉规范，不为营销临时制造另一套视觉系统。
- 数据状态优先使用标签、时间和说明表达，不能只靠红绿颜色传达风险或结论。
- 营销页使用真实产品界面和真实可验证的流程，不展示未上线功能或虚构绩效。
- 统一产品内、官网、社交媒体和邮件中的品牌名称、免责声明、数据口径与 CTA。

## 5. 推广策略

### 5.1 先聚焦一个主要用户群

建议首阶段聚焦：

> **有一定市场经验、会同时关注多个标的，但缺少稳定研究记录与复盘习惯的个人投资者。**

不建议一开始同时面向纯新手、专业量化用户、券商客户、教育机构和源码买家。C 端产品与源码 / 私有部署业务应使用不同入口和销售文案。

### 5.2 获客渠道与内容方向

| 渠道 | 内容 / 动作 | 目标 |
|---|---|---|
| Learn 与搜索 | 多市场基础、研究方法、风险概念、工具解释；每篇文章连接到相关产品练习 | 累积长期可发现的内容入口 |
| 短内容平台 | 发布图表观察方法、研究清单、模拟复盘案例；不发布具体荐股结论 | 建立品牌认知并引导体验 |
| 社群与创作者合作 | 合作做产品演示、学习活动或模拟复盘挑战；明确商业合作关系 | 借助可信创作者触达目标用户 |
| 用户邀请 | 邀请好友共同完成学习 / 模拟挑战，或获得透明、有限的产品权益 | 鼓励真实推荐，避免纯刷邀请 |
| 产品内分享 | 分享脱敏的图表批注、研究模板或规则回放，接收者可查看来源和限制 | 让用户成果自然传播 |
| 产品演示与案例 | 用从自选到复盘的完整演示展示价值，而非单页功能罗列 | 提升注册后的激活和转化 |

内容建议形成固定栏目，而非追逐每日热点：

1. **一张图看懂**：展示如何提出问题、核对数据，不给买卖结论。
2. **研究记录复盘**：展示假设如何被验证或推翻，说明数据时间。
3. **模拟过程拆解**：关注计划与执行，不以模拟收益排名吸引用户。
4. **工具小课**：仓位、定投、风险和规则回放的教育性解释。
5. **产品更新日志**：公开功能变化、已知限制和修复情况。

### 5.3 推广漏斗

```text
内容 / 合作 / 邀请
        ↓
落地页：一句话价值 + 真实产品演示 + 清晰边界
        ↓
注册并完成首个研究动作
        ↓
设置自选或研究提醒
        ↓
回访查看变化 / 完成模拟练习
        ↓
形成周期复盘
        ↓
用户推荐或升级会员
```

落地页的主要 CTA 应引导用户“开始建立自己的研究清单”或“体验一次完整复盘”，而不是只让用户注册后自行摸索。

### 5.4 90 天验证节奏

| 阶段 | 重点动作 | 验证问题 |
|---|---|---|
| 第 1–2 周 | 访谈 10–15 位目标用户；测试定位、首页文案和研究卡原型 | 用户是否有持续记录、追踪和复盘的真实痛点？ |
| 第 3–6 周 | 上线研究卡、提醒偏好和自选变化摘要的最小闭环；发布首批高质量 Learn 内容 | 用户能否完成首次价值体验？摘要是否真的带来有用回访？ |
| 第 7–10 周 | 加入研究记录保存 / 前后对比、每周复盘邮件或站内摘要（用户可选） | 用户是否持续使用并积累过程资产？ |
| 第 11–13 周 | 对活跃用户测试会员意愿与价值排序；优化内容渠道和注册漏斗 | 用户愿意为哪种持续价值付费？哪个渠道带来高质量用户？ |

不要仅凭“注册数”判断成功。阶段结束后根据行为数据和用户反馈决定继续、调整或停止某项功能。

## 6. 会员与商业化建议

订阅可以作为 C 端的主线之一，但应在用户形成持续使用和信任后测试付费意愿。

| 层级 | 价值方向 |
|---|---|
| 免费 | 基础行情与图表、有限自选 / 提醒、模拟体验、少量 AI 体验、基础学习内容 |
| Pro | 更完整的研究历史与对比、更多自选 / 提醒、较高 AI 配额、扩展复盘、规则回放或高级导出 |
| BYOK | 用户使用自己的 AI / 行情凭证；付费价值侧重研究工作流、历史资产与复盘功能，而非模型调用本身 |

具体额度和价格应通过成本测算与用户测试确定。避免承诺无限 AI；明确免费额度、重置周期、BYOK 处理方式和数据供应商商业使用许可。

其他收入来源可以作为独立业务线评估：

- 源码、私有部署、定制服务：面向团队或机构，和 C 端订阅分开呈现。
- 教育或白标产品：先验证学习路径和机构需求，再考虑按席位或授权收费。
- 数据或券商合作：须先核实许可、商业披露与目标市场的监管要求。

不要把付费“策略信号”、个性化荐股或收益承诺作为默认会员权益。涉及投资建议、金融推广、行情再分发和跨境服务时，应针对实际经营地区咨询专业法律意见。

## 7. 指标与验证

### 产品行为指标

- **激活率**：新注册用户在首个会话或限定时间内完成“添加自选 + 创建研究记录 / 提醒”。
- **核心闭环完成率**：用户完成研究记录、变化回访、模拟练习、复盘中的关键步骤比例。
- **留存**：按注册周观察 D1、D7、D30，并按用户类型区分；不将日活作为唯一目标。
- **研究资产积累**：每位活跃用户保存的研究记录、有效复查和复盘数量。
- **通知质量**：摘要打开、后续产品动作、关闭率、退订率和用户反馈。

### 商业指标

- 试用转付费、续费与取消原因。
- 不同功能的实际使用和付费意愿。
- 获客渠道的注册激活率与留存质量，而不只比较曝光和点击。
- AI 与外部数据的单位用户成本、毛利和供应商限制。

先建立基线，再设目标值；分市场、渠道和用户类型分析，避免只优化单一总体数字。

## 8. 风险与原则

1. **数据许可**：逐一确认行情、新闻、财报和其他数据源是否允许面向付费用户展示、缓存、邮件摘要、导出或再分发。
2. **合规与宣传**：避免荐股、收益承诺和未经验证的绩效宣传；按经营地区审查服务边界。
3. **AI 可靠性**：显示来源与时间，区分事实和生成内容；提供纠错反馈；不能静默填补缺失数据。
4. **隐私与安全**：研究记录、交易日志和 BYOK 凭证属于敏感用户数据；提供清晰的数据控制与删除能力。
5. **通知体验**：用户控制频率和渠道，提供退订；不以焦虑和过度推送换短期打开率。
6. **产品聚焦**：优先做研究—提醒—复盘闭环；社区、全市场扫描、实盘交易等高成本方向先验证需求与合规条件。
7. **业务分线**：C 端 SaaS 与源码 / 私有部署在官网中明确分流，避免用户不清楚买到的是在线服务还是软件交付。

## 9. 当前优先级结论

建议近期按以下顺序推进：

1. 打磨首次使用引导，让用户建立第一张研究卡或完成一次自选 + 提醒。
2. 做用户可控的自选变化摘要，并链接回上次研究记录。
3. 保存 AI 研究结果，支持前后变化对比并明确数据时间与来源。
4. 把模拟交易计划与复盘记录关联，先服务过程学习，不做收益榜。
5. 持续发布有产品内练习入口的教育内容，验证自然流量与激活质量。
6. 获得留存和成本基线后，再测试 Pro 套餐、额度和价格。

判断每个新功能时先问：它是否让用户更好地记录、追踪、验证或复盘？是否有明确的数据来源和使用边界？能否测量对激活、留存或付费的影响？若答案不清楚，先做用户研究或原型测试，不急于开发。
