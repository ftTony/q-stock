# 图表渲染选型：Canvas vs SVG

面向 Q-Stock 内各类图表（主行情图、面板附属图、营销示意）。更广的金融图表技术地图见 [金融图表常用技术](./financial-chart-tech.md)。

**核心判断：数据点多、要高频刷新 → Canvas；元素少、要交互/可访问 → SVG。**

## 1. 快速口诀

```text
点数少 + 要交互/样式     → SVG
点数多 + 要流畅滚动缩放 → Canvas
两者都要（如可点选的大数据图）→ Canvas 主图 + SVG/HTML 叠加层（坐标轴、tooltip、标注）
```

## 2. 适合 Canvas

| 场景 | 原因 |
|---|---|
| K 线、分时、Tick、深度图 | 点很多（千～十万级），DOM/SVG 节点会卡 |
| 实时推送、拖拽缩放、十字光标 | 每帧重绘一块像素，比改大量 DOM 便宜 |
| 热力图、大量散点、Volume Profile 密集区 | 像素绘制成本可控 |
| 需要导出成 PNG 截图 | 本身是位图，截图路径简单 |

**代价**

- 不是 DOM：单独点选 / hover 要自己算命中
- 无障碍、CSS 样式、SEO 都更弱
- 高 DPI 要自己处理 `devicePixelRatio`

## 3. 适合 SVG

| 场景 | 原因 |
|---|---|
| 饼图 / 环图、少量柱 / 折线、对比图 | 几十个 `<path>` / `<rect>` 即可 |
| 需要精确点击、tooltip、高亮单根柱 | 每个图形是元素，事件天然好绑 |
| 图标、示意、营销插图、小 sparkline | 矢量清晰、易主题色 / 暗色切换 |
| 要打印、放大、CSS 动画 | 分辨率无关，可用 CSS / `currentColor` |

**代价**

- 元素一多（大致几百上千）就慢
- 复杂动画和海量重绘不如 Canvas

## 4. Q-Stock 现状对照

| 图表 | 技术 | 说明 |
|---|---|---|
| 主行情 K 线 / 分时（`candle-chart` / klinecharts） | Canvas | 大量蜡烛 + 缩放平移 + 截图导出 |
| 筹码分布（`symbol-chips-chart`） | SVG | 面板级柱状，元素可控 |
| 资金饼 / 环图（`symbol-funds-donut`） | SVG | 少量扇区，易绑交互与主题色 |
| 做空相关小图（`symbol-short-chart`） | SVG | 附属面板，非高频全量重绘 |
| 分析对比小图（`analysis-compare-panel`） | SVG | 对比条数少，点选/标注友好 |
| 营销示意（`marketing-quote-level-visuals`） | SVG | 静态/轻动效插图 |

Volume Profile、深度图若点密度变大导致卡顿，再评估迁到 Canvas；当前面板级小图继续 SVG。

## 5. 混合方案（需要时）

主图用 Canvas 画密集数据，交互层用 SVG 或 HTML：

```text
┌─────────────────────────────────┐
│  HTML / SVG：tooltip、标注、按钮 │
├─────────────────────────────────┤
│  Canvas：K 线 / 分时 / 成交量    │
├─────────────────────────────────┤
│  Canvas 或 SVG：坐标轴、网格     │
└─────────────────────────────────┘
```

命中检测常见做法：Canvas 侧维护与视口同步的数据索引（按 x 二分查蜡烛），再把结果交给上层 DOM 展示。

## 6. 选型检查清单

做新图前问三句：

1. **视口内大概多少图元？** 少于约 200 → 优先 SVG；上千且要跟手 → Canvas。
2. **刷新频率？** 盘中每秒多次 / 拖拽连续重绘 → Canvas；用户点一下才变 → SVG 通常够。
3. **交互粒度？** 要点选「某一根柱 / 某一扇区」且逻辑简单 → SVG；只是十字线跟价 → Canvas 自算命中即可。
