# 策略与回测方向：用规则削弱贪婪与恐惧

> 外部项目启发与产品方向补充。本文聚焦 Q-Stock 的策略、规则回放和模拟交易闭环，不替代[交易策略与回测 PRD](./prd/strategy-and-backtest.md)或[模拟盘风险控制 PRD](./prd/risk-control.md)。

## 1. 产品主张

Q-Stock 的策略与回测不应以「找出收益最高的策略」为目标，而应帮助用户在行动前写清规则、在历史中理解规则的代价，并在模拟交易后检查自己是否遵守规则。

**核心闭环：**

```text
明确规则 → 历史回放 → 看见收益与风险的交换 → 模拟执行 → 复盘执行偏差 → 修正规则
```

这条链路对应产品主张：借助可检查的规则和复盘，尽量削弱贪婪、恐惧等人性弱点。系统不能消除情绪，也不应给用户贴「贪婪」「恐惧」标签；它能做的是把临场决定变成可提前设定、可事后检查的过程。

### 设计原则

1. **规则先于结论**：用户先选或写明入场、退出、仓位和风险边界，再看结果。
2. **风险先于收益**：最大回撤、亏损期、交易次数和持仓时间与收益一同展示，不只突出累计收益。
3. **解释先于排名**：解释规则何时有效、何时失效，以及哪些假设影响结果；不设策略排行榜或收益竞赛。
4. **模拟而非自动执行**：回测结果可以生成模拟单草稿或策略标签，但不自动下单，更不连接实盘执行。
5. **复盘行为，不评判情绪**：记录是否按规则执行、是否偏离预设计划；情绪标签只由用户自愿填写。

## 2. 五个参考项目能带来的启发

|---|---|---|
| [TradingAgents](https://github.com/TauricResearch/TradingAgents) | 基本面、技术面、新闻/情绪和风险等不同视角分别分析，再呈现讨论与风险。 | 作为回测报告的可选解释层：先由确定性回放引擎计算结果，再让 AI 总结规则的表现区间、失败情形和待验证假设。AI 不负责伪造或重算收益。 |

| [cinar/indicator](https://github.com/cinar/indicator) | 丰富的技术指标与策略/回测计算参考。 | 当前已有 MA、EMA、BOLL、RSI、MACD，先复用现有能力；确认指标缺口后再评估其 [TypeScript 版本](https://github.com/cinar/indicatorts)，不要为接入 Go 库增加服务边界。 |
| [OpenTerminal](https://github.com/ErTasselli/OpenTerminal) | 图表指标、财报/经济日历、信息面板，以及多数据源和缓存降级等终端体验。 | 可辅助回测的事件上下文和图表交互，但优先级低于规则回放、交易成本、风险展示和复盘闭环。公开数据端点须先核对稳定性、使用条款和产品适用性。 |

这些项目是功能与产品设计的参考，不意味着应复制其代码、数据源或系统架构。

### Vibe-Trading 的取舍

Vibe-Trading 是覆盖多数据源、多个回测/因子分析工具和 Agent 工作流的个人交易研究工具包，范围远大于 Q-Stock 当前的产品目标。对 Q-Stock 来说，最有价值的不是复制它的大型工具箱，而是它把**用户自己的交易记录**作为研究输入这一点：

1. 总结交易行为和执行模式，作为复盘线索，而不是给用户做心理诊断。
2. 从记录中提出少量「如果……那么……」候选规则，并显示每条规则对应的历史样本和证据。
3. 由用户修改、确认或拒绝候选规则，不能由 AI 自动把历史盈利交易变成正式策略。
4. 对确认后的规则做历史回放，并和真实模拟执行过程并列查看；差异用于理解规则和执行，不宣传「照做就能多赚」。

回测稳健性检验（例如滚动区间验证、重采样稳定性分析）可在基础回放可信且样本充分后再评估。Vibe-Trading 的因子库、复杂优化、多 Agent 团队、广泛券商/市场连接及实盘执行均不属于 Q-Stock 当前范围。

## 3. 与 Q-Stock 现状的衔接

Q-Stock 已有以下基础，可优先组合而非另起一套：

- 行情门面和 K 线数据：`src/lib/market`，涵盖美股、港股、A 股和加密资产。
- 图表常用指标：MA、EMA、BOLL、RSI、MACD。
- 模拟交易：纸面账户、持仓、订单和成交流程。
- AI 个股工具：报价、K 线特征、新闻、财报和趋势分析。
- 交易复盘：`/api/ai/review` 已按模拟成交与持仓生成过程复盘。
- 规划文档：[策略与回测 PRD](./prd/strategy-and-backtest.md)已定义策略模板、策略标签、单标的日 K 回放和分期范围；[风险控制 PRD](./prd/risk-control.md)规划了下单风险摘要、情绪自检和账户级约束。
- 个股页交互落点：[个股页 UI 改版](./prd/symbol-trading-ui.md)把闭环收成右栏 **计划 | 下单 | 复盘**（盘口/分笔为行情辅层），与策略实验室、模拟盘、过程复盘衔接，而不是另做一套量化工作站。

因此建议把策略实验室定位为现有「看盘 → AI 分析 → 模拟 → 复盘」闭环的规则层，而不是独立的量化平台；个股页负责「本标的」上的计划、执行与偏差对照，完整规则编辑与跨标的复盘仍在 `/strategies` 与 `/review`。

## 4. 产品分期建议

以下顺序与现有 PRD 的 P0/P1/P2 保持一致，具体验收以 PRD 为准。

### P0：策略模板与模拟交易标签

- 提供少量透明、可解释的策略模板，例如定投、均线规则、突破与固定止损、按风险预算计算仓位。
- 展示每条规则的适用条件、退出条件、仓位限制和风险说明。
- 用户可以复制模板、记录自己的版本，并在模拟下单时附上策略标签。
- 生成的模拟单草稿必须由用户检查和提交；策略规则不触发自动交易。

**目的：**先帮助用户在交易前形成计划，不以复杂回测或 AI Agent 数量作为上线门槛。

### P1：单标的历史规则回放

- 首版只做单标的、日 K、有限历史长度和有限交易次数。
- 采用确定性规则执行器；同样的输入、规则版本和参数应得到相同结果。
- 展示权益曲线、买入持有对照、交易明细、累计收益、最大回撤、胜率、盈亏比、交易次数及数据区间。
- 明确计入或标注手续费、滑点、成交时点和数据缺失假设。
- 回放完成后可保存报告，记录策略版本、参数、行情数据区间、生成时间和假设。

**目的：**让用户检验自己能否接受规则的完整过程，包括连续亏损和长时间落后于基准，而不只看结果好看的区间。

### P2：复盘与可选 AI 解读

- **已落地（规则实验室）**：同标的同区间双规则对比、单一参数小表（2–5 档）、多标的篮 Worker 依次回放、只读分享链、回放结果 AI 过程解读（强调过拟合）。
- 对比两条规则时保持相同标的、日期区间、基准和成本假设。
- AI 只解释已计算的结果，指出规则表现较差的阶段、可能的过拟合和需要进一步验证的假设。
- 将策略标签与模拟成交、AI 交易复盘连接，帮助用户检查执行偏差，而非鼓励追逐近期最优策略（个股页复盘 Tab 仍可后置）。
- 基于 Q-Stock 已有的模拟成交，归纳可观察的执行模式（例如偏离原计划、过早退出、重复加仓），并给出有样本依据的候选规则草稿；用户确认后才能保存或回放。
- 将确认规则的回放结果与同一用户的模拟记录并列呈现，注明比较口径、样本范围和假设；不把反事实收益差额作为主标题或收益承诺。
- 更大组合优化与宽参数扫描仍须单独容量与防偏差设计后再排期。

**后续可选项：**允许用户主动导入自己的历史交易记录，用于同类行为复盘。导入前须说明用途、字段和保留期限；尽量只保留解析后的必要记录，提供删除入口，并在发送给 AI 前取得明确同意。首版不需要连接外部券商账户。

## 5. 如何把“削弱贪婪、恐惧”落到交互

| 典型冲动 | 产品机制 | 推荐措辞 |
|---|---|---|
| 因上涨而追高、临时加仓 | 下单前显示预设入场条件、仓位占权益比例和可选失效价；AI 草稿明确标记为未提交。 | 「这笔模拟单尚未提交。请先确认入场条件与风险范围。」 |
| 因下跌而恐慌卖出或报复交易 | 让用户回看预先设定的退出条件和账户规则；触及规则时提醒，而非直接替用户下单。 | 「当前价格接近你记录的失效条件，请检查原计划是否仍适用。」 |
| 连胜后放大仓位 | 显示连续交易记录、单笔风险和账户级上限；按规则限制仓位建议，不突出连胜。 | 「本次仓位超过你设定的单笔风险范围。」 |
| 回测后只挑最好参数 | 默认展示完整区间和基准；参数对比必须标出区间、交易数和多重尝试风险。 | 「历史表现依赖所选区间与参数，不代表未来结果。」 |
| 亏损后频繁改规则 | 保留策略版本与修改记录；新版本重新回放，不覆盖旧报告。 | 「规则已修改。新旧版本结果分开展示，便于比较假设变化。」 |
| 从历史盈利中只挑符合偏好的交易 | 交易记录分析展示全部符合条件的样本、反例和数据不足项；候选规则须由用户确认。 | 「这是基于已有记录整理的假设，不代表未来仍有效。」 |

情绪自检宜为可选、非诊断、非阻断。重点记录的是用户在事前定下的规则和事后执行结果，不推断用户心理状态。

## 6. 回测可信度底线

策略回放本身容易制造虚假的确定感。最低限度要做到：

- **避免前视偏差**：信号只能使用当时已经收盘并可获得的数据；不能用当日收盘价生成信号后又假设同价成交。
- **避免数据泄漏**：财报、新闻、公司行动等数据只能在实际公布时间后参与判断；若数据源无法提供历史时点版本，应明确说明该数据不用于历史回测。
- **计入交易摩擦**：手续费、滑点、跳空和无法成交情形至少要能说明；回放成交规则应固定且可复现。
- **标注样本边界**：展示所用标的、区间、K 线数量、缺失数据与市场状态；不把单个标的或单段历史推广成普遍结论。
- **控制参数试错**：不默认搜索成百上千组参数并只展示最好的一组；参数越多，越要提醒过拟合并使用独立验证区间。
- **谨慎使用基准**：同一市场、同一时间区间、同一资金口径；多市场或跨币种比较须说明换算方式。
- **结果不等于建议**：报告应明确为教育和研究用途，不构成投资建议，也不保证未来表现。

建议把这些约束纳入回放结果格式和测试用例，而不只放在页面免责声明里。

## 7. 成功标准

不要只用回测收益率或用户创建的策略数量衡量成功。更贴合产品主张的指标包括：

- 用户能否完成「选规则 → 查看风险与假设 → 运行回放 → 保存结果」。
- 模拟交易中附有策略标签的订单比例，以及复盘时能否查看对应规则版本。
- 用户在模拟交易中遵守预先设定退出条件和仓位限制的比例。
- 回放报告中风险指标、基准和成本假设的可见率。
- 用户是否能识别策略表现较差的区间，是否能区分历史结果与未来保证。
- 交易记录分析中候选规则的证据覆盖率、用户修改/拒绝比例，以及确认规则后是否完成回放和复盘。

指标只用于评估产品是否支持更有纪律的决策，不应以增加交易次数、提高下单转化或追求更高回测收益为优化目标。

## 8. 建议结论

1. 以现有[策略与回测 PRD](./prd/strategy-and-backtest.md)为执行基线，优先完成 P0，再做有限范围的单标的规则回放。
2. 复用当前行情、K 线指标、模拟交易和复盘能力；先建立可复现、可审计的回放结果，不先引入多 Agent 框架、复杂因子系统或大量指标依赖。
3. 个股页按[symbol-trading-ui.md](./prd/symbol-trading-ui.md)落地：P0 计划默认 + 策略标签下单；P1 本标的回放摘要；P2 复盘偏差 Tab——与本文分期一一对应。
4. 在回放可信后，借鉴 Vibe-Trading 的交易记录分析和 Shadow Account 思路，先从 Q-Stock 模拟成交中提炼用户可确认的规则草稿；外部记录导入后置。
5. 将 AI 用在规则解释、风险提示和执行复盘；收益、回撤和交易记录由确定性逻辑计算。
6. 让“削弱贪婪、恐惧”落在交易前计划、风险边界、冷静提示和事后复盘，而不是靠情绪评分、收益排行或自动下单。
